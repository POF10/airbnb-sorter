# Расширение Chrome — дизайн

Дата: 2026-10-01
Статус: согласован, ждёт плана реализации
Основа: [Airbnb Sorter — дизайн](2026-09-28-airbnb-sorter-design.md) (userscript v0.1.0)

## Цель

Дать Airbnb Sorter обычным людям без Tampermonkey: расширение Chrome, которое ставится в один клик из Chrome Web Store и делает то же, что userscript. Tampermonkey-версия остаётся и выпускается из того же кода.

Критерии успеха:

- Расширение, загруженное как распакованное из `dist/extension/`, показывает кнопку «↕ Сортировать все» на поиске жилья на `www.airbnb.com` и на национальном домене (например, `www.airbnb.co.uk` или `ru.airbnb.com`).
- Сбор, слой, карта и кэш работают так же, как в userscript: поиск «Рига, 3 ночи, 2 гостя» собирается с тем же результатом.
- Повторное открытие того же поиска после перезагрузки страницы берётся из кэша.
- В окне расширения можно выбрать язык интерфейса; выбор сохраняется.
- Пакет проходит требования Chrome Web Store: Manifest V3, без внешнего кода, минимальные права.
- `npm test` проходит, Tampermonkey-сборка продолжает работать.

## Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Цель | Сразу под Chrome Web Store; локальная проверка через «Загрузить распакованное» |
| Запуск | Кнопка на странице, как в userscript (а не клик по иконке расширения) |
| Название | «Price Sorter for Airbnb» / «Сортировка по цене для Airbnb»; репозиторий и userscript остаются «Airbnb Sorter» |
| Настройки | Окно по клику на иконку расширения: язык и блок «Поддержать разработчика» |
| Пожертвования | Пока адреса-заглушки на `example.com`, чтобы видеть интерфейс; настоящие страницы пользователь заведёт позже |

## Выбранный подход

**Один контент-скрипт в изолированном мире, без фонового процесса.** Это третья точка входа рядом с `src/userscript.js` и `dev/inject.js`: вся логика по-прежнему запускается через `start(env)` из `src/main.js`.

- Запросы к Airbnb идут из вкладки пользователя, same-origin, с его сессией, как в userscript. Фоновый процесс и `host_permissions` для них не нужны.
- Leaflet входит в сборку (Chrome Web Store запрещает загружать исполняемый код извне).
- Кэш и настройки лежат в `chrome.storage.local`.

Отклонённые варианты:

- **Запросы из фонового процесса.** Больше кода и прав, запросы шли бы без контекста страницы; выигрыша нет.
- **Кэш в `localStorage` страницы** (как в `inject`-сборке). Код кэша не менялся бы, но лимит 5 МБ делится с данными самого Airbnb, кэш отдельный на каждый домен, и окно расширения не может прочитать оттуда настройки.

## Архитектура

```
src/userscript.js        ─┐
dev/inject.js            ─┼─ start(env)  →  collector, cache, settings, viewer
src/extension/content.js ─┘
src/extension/popup.js   ──  settings, i18n   (кода Airbnb не касается)
```

### Контракт окружения

```js
env = {
  L,                    // Leaflet
  leafletCss,           // строка CSS
  storage: {
    get(key, fallback), // значение или Promise
    set(key, value),    // void или Promise
  },
  onSettingsChange,     // необязательно: (callback) => void; есть только у расширения
}
```

`storage` становится асинхронным контрактом: потребители делают `await`, поэтому синхронные адаптеры (Tampermonkey, `localStorage`) продолжают работать без изменений.

| Сборка | `L` и CSS | `storage` | `onSettingsChange` |
|---|---|---|---|
| Tampermonkey | `@require` / `@resource` с unpkg | `GM_getValue` / `GM_setValue` | нет |
| inject | unpkg с проверкой хэша | `localStorage` | нет |
| Расширение | из сборки (`leaflet` из npm) | `chrome.storage.local` | `chrome.storage.onChanged` |

| Файл | Что делает |

| `src/extension/domains.js` | Список доменов Airbnb |

## Манифест

Manifest V3, собирается при сборке.

```json
{
  "manifest_version": 3,
  "name": "__MSG_extName__",
  "description": "__MSG_extDescription__",
  "default_locale": "en",
  "version": "<из package.json>",
  "minimum_chrome_version": "114",
  "icons": { "16": "icons/16.png", "32": "icons/32.png", "48": "icons/48.png", "128": "icons/128.png" },
  "permissions": ["storage"],
  "content_scripts": [{ "matches": ["<по одному шаблону на домен>"], "js": ["content.js"], "run_at": "document_idle" }],
  "action": { "default_title": "__MSG_extName__", "default_popup": "popup.html" },
  "options_ui": { "page": "popup.html", "open_in_tab": false }
}
```

- **Права:** только `storage`. Доступ к сайтам задаётся списком `matches`; при установке Chrome покажет предупреждение о чтении и изменении данных на сайтах Airbnb.
- **`minimum_chrome_version: 114`:** с этой версии лимит `chrome.storage.local` равен 10 МБ; кэш занимает до ~3 МБ.
- **Фреймы:** скрипт работает только в верхнем окне (значение по умолчанию), как `@noframes` в userscript.
- **Все страницы домена, а не только `/s/…`:** Airbnb — одностраничное приложение, на поиск попадают без перезагрузки, поэтому скрипт должен быть на странице заранее. Кнопку по-прежнему показывает и прячет `launcher.js` по адресу.

### Домены

В манифесте нельзя задать регулярное выражение, как в `@include` userscript, нужен явный список. Источник — переключатель языка и региона на главной Airbnb, 2026-10-01: 70 доменов. Для каждого шаблон `https://*.airbnb.<зона>/*` (покрывает `www.` и языковые поддомены вроде `ru.airbnb.com`, `fr.airbnb.ch`).

- `airbnb.com`
- одна зона (36): `ae am at az ba be ca cat ch cl cz de dk es fi fr gr gy hu ie is it jp lt lu lv me mx nl no pl pt rs ru se si`
- `com.*` (25): `ar au bo br bz co ec ee gt hk hn mt my ni pa pe ph py ro sg sv tr tw ua vn`
- `co.*` (8): `cr id in kr nz uk ve za`

На домене, которого нет в списке, кнопки не будет. Исправление — добавить домен и выпустить версию; Tampermonkey-версия покрывает любые домены регулярным выражением.

## Хранилище

Два ключа в `storage`:

| Ключ | Содержимое |
|---|---|
| `lastCollection` | Кэш последнего сбора, формат не меняется (`v: 1`) |
| `settings` | `{ language: 'auto' \| 'en' \| 'ru', sort: <id сортировки> }` |

`src/settings.js`:

- `loadSettings(storage)` возвращает настройки с подстановкой значений по умолчанию (`language: 'auto'`, `sort: 'price-desc'`). Неизвестные значения заменяются значениями по умолчанию, ошибка хранилища даёт настройки по умолчанию.
- `saveSettings(storage, patch)` читает, объединяет и записывает; ошибка записи пишется в консоль и не ломает интерфейс.

Адаптер расширения:

```js
storage = {
  get: async (key, fallback) => (await chrome.storage.local.get(key))[key] ?? fallback,
  set: (key, value) => chrome.storage.local.set({ [key]: value }),
};
```

Кэш в расширении общий для всех доменов Airbnb; ключ кэша содержит полный адрес поиска, поэтому поиски с разных доменов не путаются.

## Настройки

### Окно расширения

Открывается кликом по иконке на панели Chrome и через «Параметры расширения».

```
Price Sorter for Airbnb                 v0.2.0
Откройте поиск жилья на Airbnb и нажмите
«↕ Сортировать все».

Язык   [ Авто ▾ ]      Авто · English · Русский

♥ Поддержать разработчика
[ Ko-fi ] [ Buy Me a Coffee ] [ PayPal ]

GitHub · Сообщить о проблеме
```

- Язык самого окна: выбранный в настройке, при «Авто» — язык интерфейса Chrome (русский или английский).
- Смена языка сохраняется сразу, без кнопки «Сохранить».
- Блок поддержки показывает по кнопке на каждую запись `SUPPORT_LINKS` из `src/config.js`; кнопка открывает страницу в новой вкладке. При пустом списке блока нет.

### Адреса для пожертвований

`SUPPORT_LINKS` — список `{ label, url }`, первая запись считается основной. Сейчас в нём три заглушки на `https://example.com/support/…` (зарезервированный домен, чужих страниц пожертвований за ним нет). Пока в списке есть хоть одна заглушка, `npm run build` печатает предупреждение; публиковать с заглушками нельзя — это пункт проверки перед выпуском.

### Язык

- `auto` — как сейчас: язык страницы Airbnb, затем язык браузера (`detectLocale`).
- `en`, `ru` — принудительно.

Открытые вкладки Airbnb узнают о смене через `chrome.storage.onChanged`: текст кнопки запуска меняется сразу, слой получает новый язык при следующем открытии (закрытый слой пересоздаётся; открытый и идущий сбор не трогаются).

### Сортировка

Слой запоминает последнюю выбранную сортировку в `settings.sort` и открывается с ней. Отдельного элемента в окне расширения для этого нет. Работает и в userscript.

### Ссылка поддержки в слое

В шапке слоя — небольшая ссылка «♥» с подсказкой «Поддержать разработчика», ведёт на первую запись `SUPPORT_LINKS`. Она есть во всех сборках, чтобы её видели и пользователи Tampermonkey. При пустом списке ссылки нет.

### Что остаётся без настроек

В userscript окна настроек нет: язык всегда «Авто». Темп запросов, срок жизни кэша и положение кнопки не настраиваются.

## Защита от двойного запуска

Если установлены и userscript, и расширение, кнопок было бы две. `start()` через `src/guard.js` ставит атрибут `data-airbnb-sorter` на `<html>` и выходит, если он уже стоит: изолированные миры делят один DOM, поэтому работает тот, кто запустился первым. Этот же флаг заменяет `window.__airbnbSorter` в `inject`-сборке.

## Обработка ошибок

- **Хранилище недоступно или переполнено.** Чтение даёт «кэша нет» и настройки по умолчанию, запись пишет предупреждение в консоль. Сбор и показ результата от хранилища не зависят.
- **Расширение обновилось, а вкладка открыта.** Старый контент-скрипт остаётся на странице, вызовы `chrome.storage` в нём бросают «Extension context invalidated». Это та же ветка, что и недоступное хранилище: слой продолжает работать без кэша до перезагрузки страницы.
- **Ошибки сбора** — без изменений, см. основную спеку.

## Сборка и выпуск

`npm run build` собирает всё:

| Результат | Назначение |
|---|---|
| `dist/airbnb-sorter.user.js` | Tampermonkey; коммитится, адрес установки и автообновления |
| `dist/airbnb-sorter.inject.js` | Запуск из консоли |
| `dist/extension/` | Папка для «Загрузить распакованное»: `manifest.json`, `content.js`, `popup.html`, `popup.js`, `popup.css`, `icons/`, `_locales/` |
| `dist/airbnb-sorter-extension-<версия>.zip` | Для Chrome Web Store и для релиза на GitHub |

- Новые зависимости разработки: `leaflet@1.9.4` (та же версия, что в userscript) и `fflate` для zip. В рантайме зависимостей по-прежнему нет: всё внутри сборки.
- PNG-иконки рисует `scripts/make-icons.mjs` (без зависимостей), они коммитятся; сборка их только копирует. Иконка — белая стрелка «↕» на тёмном скруглённом квадрате, как кнопка запуска.
- `dist/extension/` и zip в git не попадают (`dist/*` уже в `.gitignore`).
- Версия одна на всё: `package.json` → заголовок userscript и манифест. Этот выпуск — **0.2.0** для обеих сборок, так как меняется и общий код.
- Порядок выпуска дополняется: приложить zip к релизу на GitHub и загрузить его в Chrome Web Store.

## Тестирование

Юнит-тесты (`node:test`):

- `cache`: те же сценарии с синхронным и с асинхронным хранилищем; отказ хранилища при чтении и записи.
- `settings`: значения по умолчанию, отбраковка неизвестных значений, слияние при записи, отказ хранилища.
- Адаптер `chrome.storage.local` на поддельном `chrome`.
- `manifest`: версия из `package.json`, по шаблону на каждый домен, форма шаблонов, набор прав ровно `["storage"]`.
- `domains`: нет повторов; каждый домен принимается регулярным выражением из заголовка userscript.
- `i18n`: в обоих словарях одинаковый набор ключей, включая строки окна расширения.
- Защита от двойного запуска.

- `config`: адреса — https, распознавание заглушек.

Стенд разработки:

- слой берёт Leaflet из сборки, как расширение, а не с unpkg, — так стенд проверяет ту же сборку Leaflet;
- добавляется страница окна расширения (`/popup.html`) с хранилищем на `localStorage`, чтобы проверять её вид и оба языка без установки.

Проверка перед приёмкой: общий код (асинхронный кэш, настройки, защита от двойного запуска) прогоняется на живом Airbnb через `dist/airbnb-sorter.inject.js`, как при приёмке v0.1.0. Сам `content.js` на живой странице без установки не запустить: CSP Airbnb не даёт подгрузить его с localhost, а передавать 400 КБ текстом нецелесообразно. Специфичное для расширения проверяется по частям: Leaflet из сборки — на стенде, адаптер `chrome.storage` и манифест — тестами, всё вместе — приёмкой в Chrome.

Приёмка пользователем в его Chrome (`chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → `dist/extension/`):

1. Кнопка появляется на поиске на `www.airbnb.com` и на одном национальном домене; на главной и на странице объявления её нет.
2. Сбор проходит, карточки и карта с плитками видны.
3. После перезагрузки страницы тот же поиск открывается из кэша.
4. Смена языка в окне расширения меняет текст кнопки на открытой вкладке.
5. Выбранная сортировка сохраняется между открытиями.
6. При включённом userscript в Tampermonkey кнопка одна.

## Риски

- **Жалоба Airbnb.** Правила Airbnb запрещают автоматический сбор. Магазин сам за это обычно не отклоняет, но по жалобе на сбор данных или товарный знак расширение могут снять. Смягчение: название в форме «for Airbnb», без логотипа и фирменных цветов Airbnb в иконке.
- **Плитки OpenStreetMap.** Общий сервер плиток не рассчитан на большую аудиторию. Адрес плиток задан в одном месте (`src/viewer/map.js`); при росте числа пользователей нужен другой источник.
- **Список доменов устаревает.** Новый домен Airbnb не получит кнопку до обновления расширения.
- **Проверка в магазине.** Срок от пары дней до пары недель; доступ к 70 доменам может вызвать вопросы, ответ на них — в обосновании прав.
- **Зависимость от структуры страниц Airbnb** — как у userscript, см. основную спеку.

## Вне этого выпуска

- Firefox и другие магазины расширений (Edge ставит расширения из Chrome Web Store).
- Запуск по клику на иконку расширения и работа на доменах вне списка.
- Окно настроек в userscript.
- Языки интерфейса кроме английского и русского.
- Публичный сайт, принимающий ссылку поиска.
- Сама публикация в Chrome Web Store.
